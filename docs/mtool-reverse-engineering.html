Reverse engineering · 证据报告

MTool 是怎么工作的

对象：Windows 客户端 MTool.zip、Android 主程序 mtool_v55_24.apk 及三个引擎包。 方法：纯静态分析（ZIP 结构、PE 导入表与字符串、V8 字节码字符串常量、AXML 字符串池、明文 JSON 资源、运行时插件包）。

未做动态运行（本机无 Windows / Android 环境） 凡属推断均已标注 2026-10-20

01一句话结论

MTool 不是一个"翻译器"，而是一个游戏进程内注入框架 + 文本总线 + 翻译渲染管线。翻译只是它跑在总线上的一条业务流；同样的通道还能改金币、解锁道具、换字体、注入按键。

02证据链

它是 NW.js 应用，不是 ElectronMTool/Tool/package.json

"main": "www/index.html"、chromium-args: "--disable-web-security --enable-node-worker"，同目录躺着 nw.exe、nw.dll（195 MB）、node.dll、v8_context_snapshot.bin。依赖只有四个：ws（本地 WebSocket）、legacy-encoding（Shift-JIS/GBK）、pe-library + resedit（直接改写 PE 文件，用于注入器与容器启动）。

主逻辑有三层保护www/loader.js

① evalNWBin() 加载 loader.bin.<nw版本>（V8 二进制，与 NW.js 版本强绑定）；② loader.bin.ff（26 MB）交原生扩展 new MToolExt().ExecuteBytecodeArrayBuffer() 执行；③ www/data/ 下 216 个数字命名模块（11.2 MB）全部加密。

每个引擎一个注入 DLLTool/loaders/ · 41 个文件

从 DLL 里能直接读到它要挂到什么上：RGSS 的 rb_eval_string、Ren'Py 的 PyGILState_Ensure、吉里吉里的 NI_Mtool 命名接口、Siglus 的 IATLGraphicsManager、Unity 的 0Harmony.dll。完整对照见下表。

通道是本地 WebSocket，Agent 主动连出loaders/*.dll + mtool-runtime

DLL 里有 ws://127.0.0.1:、mtool-native/1.0、mtoolsocket2、okmtool、WaitNamedPipeW（管道回退）。而运行时包里那份明文 JS 把方向写死了：client.webSocketConnect(`ws://${serverAddr}`)——是 Agent 连宿主，不是宿主连 Agent。

Protection 之外，Android 与 PC 共用同一套前端assets/node/mtoolWebRoot/

APK 里的 loader.js、loader.bin.0.67.2、loader.bin.ff、crcData（63445 B 逐字节相同）与 PC 版完全同源。差别只在宿主：PC 用 NW.js，Android 用 libnode.so+libxul.so(Gecko)+libcontent_shell(Chromium)。

移动端各引擎是"换引擎实现"，不是模拟器三个 APK

mkxp-z（libmkxp-z.so + libruby187/193/313.so + 全套 RTP）、Ren'Py（runtime-pack.tar.zst 132 MB）、EasyRPG（libeasyrpg_android.so）。只有纯 Windows 引擎才落到 Winlator（Proton 9/10/11 + Wine Mono）。

四种注入方式（客户端自带文案即功能清单）

  • 主动注入：loaders\inject.exe 启动游戏并注入。
  • 被动注入：把 winmm.dll / version.dll 写进游戏目录，靠 DLL 搜索顺序在启动时被加载。实体就在 loaders/loaderDLL/{wm32,wm64,ver32,ver64}——它们是混淆过的载荷（熵 5.4，尾部 50 44 43 40 周期性重复），运行时才还原成 DLL。
  • 容器分离启动 / 注入运行中的游戏（后者仅支持 MV/MZ/XP-VXAce、TyranoBuilder、Ren'Py）。
  • 生成"和工具一起启动.bat"。

04三份可以直接读的原始证据

其余代码是加密的，但运行时插件包 Tool/mtool-runtime 里有两个明文 JS（ZIP，前置 34 字节私有头）。它们恰好是整个方案的心脏。

① 引导：Agent 以 bytenode 字节码形式被"跑"起来

// mtool-runtime → node/main.js
bytenode = require('bytenode');
function launchServerWithBasePath(basePath) {
  const clientPath = `${basePath}/Client.js.${process.arch}`;
  const serverPath = `${basePath}/Server.js.${process.arch}`;
  bytenode.runBytecode(fs.readFileSync(clientPath));   // 先跑 Client
  bytenode.runBytecode(fs.readFileSync(serverPath));   // 再跑 Server（定义 initServer）
  process.chdir(process.mainModule.path + "/mtoolWebRoot");
  initServer();
}
launchServerWithBasePath(`mtoolWebRoot/loaders`);   // 失败写 serverStartFailed 文件

② 握手与鉴权：任务表 + 令牌

// mtool-runtime → node/GameNodeEMU.js（"给没有 Node 的引擎伪造 Node 环境"）
global.require = require;  global.module = module;
global.WebSocket = require("ws");
bytenode.runBytecode(fs.readFileSync(`${basePath}/Client.js.${process.arch}`));
bytenode.runBytecode(fs.readFileSync(`${basePath}/Server.js.${process.arch}`));

let serverAddr = fs.readFileSync(process.mainModule.path + "/serverURI");
client = new Client();
client.taskHandles.whoareyou = function () { return "gameServer"; };  // 注册身份
try { client.authToken = fs.readFileSync(… + "/mtoolAuthToken").toString().trim(); } catch (e) {}
client.webSocketConnect(`ws://${serverAddr}`);   // 出站连接宿主

这条设计对 macOS 直接可复用：出站连接不受任何系统限制

06为什么不能照搬到 macOS

Windows 手段macOS 现实
CreateRemoteThread + LoadLibrary需 task_for_pid，SIP 下要 root 且关闭 SIP，不可分发
winmm.dll / version.dll 搜索顺序劫持没有这个机制
全局 inline hook需 entitlement，且会破坏已签名二进制
命名管道没有（只能 Unix socket）
改写 PE无用（Mach-O）

负结果也要写清楚：全量扫描 loaders/*、www/*、Tool/*.dll，没有任何 darwin/dylib/NSApplication 相关字符串；www/rawres/apkvers/ 只列了 5 个 APK 目标。官方从来没有 macOS 版本。

07Mac 版的可行路线（按可行性排序）

引擎Mac 上的注入面判定
RPG Maker MV/MZ、TyranoBuilder启动时追加 --remote-debugging-port，走 CDP 注入页面 JSP0 · 已实测通道
Ren'Py投放可逆的 game/mtool_bridge.rpy（引擎自动加载）P1 · 可行

XP/VX/VXAcemkxp-z 自编译 macOS 版挂 Ruby 层，或 Wine 内复用原 DLLP2 · 成本最高

已用真实 Chromium 反向验证过 MV/MZ 那条路：--remote-debugging-port → /json/version → browser 级 WebSocket + Target.attachToTarget(flatten) → Runtime.evaluate 注入并取回结果；客户端用系统自带 URLSessionWebSocketTask 即可，无需任何第三方库。详见 docs/archive/v0.1/cdp-validation.md。

08方法与边界

  • 已证：宿主技术栈、注入件清单与钩子落点、通信方向与握手、四种注入方式、Android 换引擎策略、无 macOS 版本。
  • 未证：加密模块（216 个）与 V8 字节码的内部业务逻辑。对其中一个样本做过 1–64 字节重复密钥 XOR 穷举，可打印率无改善，判定为流式/分组加密后停止——这是有边界的负结果，不代表全部内容不可解。
  • 未做：任何动态运行。本机无 Windows、无 Android 运行时，也没有真实 MV/MZ 游戏样本。
  • 合规：本报告不复刻、不分发 MTool 的任何二进制、字节码或加密模块；Mac 版为净室实现，仅依据公开 API 与协议形状。
